# Purpose and scope

Help people understand current events and encounter topics they have not previously searched for. Success means useful breadth and sustained understanding, rather than reinforcing past clicks.

## Agreed direction

- Publish a shared daily written briefing and a newscast-style podcast.
- Offer personalized editions to subscribers or logged-in users.
- Let people follow topics and understand what happened over time.
- Collect information through APIs/feeds and through a desktop-enabled research contributor.
- Preserve provenance and use a common canonical information layer for every edition.
- Use GitHub Pages for project documentation and GitHub Issues to make work visible.

## Proposed, still to validate

A hybrid vector/graph approach may support semantic discovery and connected history. No database or AI provider has been selected. Editorial review, publication cadence, source coverage, personalization rules, commercial terms, and account design remain open.

## First product experiment

Proposed: manually collect a small set of public reports about one topic; turn them into a sourced event timeline; draft one daily briefing and podcast script; review whether a reader can explain what changed and what remains uncertain. This is a discovery task, not a working feature.

## Current implementation

Only the documentation site, build/deployment workflow, and GitHub collaboration structure exist. Product implementation must follow scoped issues and explicit decisions.

See [architecture](architecture.md), [editions](editions.md), and [roadmap](roadmap.md).
